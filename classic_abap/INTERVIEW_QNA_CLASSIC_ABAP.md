# 🎯 Classic ABAP & SAP Gateway (SEGW) — Interview Q&A Cheatsheet

This cheatsheet covers the exact questions asked in SAP Technical Interviews for Freshers / Junior ABAP Developers.

---

### Q1: "Can you explain the end-to-end architecture of your project?"
> *"In this project, I built a Workforce and Leave Management System where a React web portal communicates with a classic SAP ABAP backend via SAP NetWeaver Gateway (OData V2). In transaction `SE11`, I created two transparent tables: `ZEMPLY_MNG_TAB` for employee master records and `ZEMPLY_LEAVE_TAB` for leave requests. In transaction `SEGW`, I modeled the entities `Employee` and `LeaveRequest`, generated the runtime objects, and implemented the business logic in the Data Provider Extension class `ZCL_ZEMPLOYEE_SRV_DPC_EXT`. The service is registered in `/IWFND/MAINT_SERVICE` and consumed by the frontend through HTTP REST calls."*

---

### Q2: "What runtime classes are generated by SEGW when you click Generate?"
> *"SEGW generates four runtime classes:*
> 1. *`MPC` (Model Provider Class): Defines the metadata, entity types, properties, keys, and associations.*
> 2. *`MPC_EXT` (Model Provider Extension): Inherits from MPC; used if we need to modify metadata dynamically via ABAP code.*
> 3. *`DPC` (Data Provider Class): Contains the default stub implementations for CRUD-Q operations.*
> 4. *`DPC_EXT` (Data Provider Extension): Inherits from DPC. **This is where developers write custom ABAP code** (redefining methods) so that regenerating SEGW does not overwrite our logic."*

---

### Q3: "Which methods did you redefine in `DPC_EXT` for CRUD-Q operations?"
> *"I redefined the following standard methods:*
> * **Query (Read List):** `EMPLOYEESET_GET_ENTITYSET` & `LEAVEREQUESTSET_GET_ENTITYSET`
> * **Read (Single Record):** `EMPLOYEESET_GET_ENTITY` & `LEAVEREQUESTSET_GET_ENTITY`
> * **Create:** `EMPLOYEESET_CREATE_ENTITY` (using `io_data_provider->read_entry_data`)
> * **Update:** `EMPLOYEESET_UPDATE_ENTITY`
> * **Delete:** `EMPLOYEESET_DELETE_ENTITY` (cascading deletion of leaves when an employee is deleted)"*

---

### Q4: "How did you implement custom actions (like Giving a Raise or Approving a Leave)?"
> *"I created **Function Imports** in SEGW called `GiveRaise` and `ApproveLeave`. In the `DPC_EXT` class, I redefined the `/IWBEP/IF_MGW_APPL_SRV_RUNTIME~EXECUTE_ACTION` method. I read the action name from `iv_action_name`, extracted the input parameters (like `Empid` and `PercentageRaise`) from `it_parameter`, executed the salary update logic in the database, and returned the updated entity using `copy_data_to_ref`."*

---

### Q5: "How does the React frontend authenticate and prevent CSRF attacks with SAP Gateway?"
> *"SAP Gateway requires CSRF protection for any modifying HTTP methods (POST, PUT, DELETE). Before making a mutating request, the frontend sends a `GET` or `HEAD` request with the header `X-CSRF-Token: Fetch`. SAP Gateway returns a unique security token in the response header `x-csrf-token` along with session cookies. The frontend then caches this token and sends it in the `X-CSRF-Token` header for subsequent POST/PUT/DELETE requests."*

---

### Q6: "How did you resolve CORS (Cross-Origin Resource Sharing) when developing locally?"
> *"Because the React development server runs on `http://localhost:3000` and SAP NetWeaver runs on a different port/host (e.g. `http://sap-server:8000`), direct browser requests trigger CORS blocks. I resolved this by configuring a reverse proxy in Vite's `vite.config.js`. All `/sap` API requests from React are proxied internally through the Vite Node server to the SAP backend, bypassing browser cross-origin restrictions entirely."*

---

### Q7: "How do you test and troubleshoot Gateway services inside SAP?"
> *"I use two primary transactions:*
> 1. *`/IWFND/MAINT_SERVICE`: To register services, assign system aliases, and view service status.*
> 2. *`/IWFND/GW_CLIENT`: The SAP Gateway Client tool to execute HTTP requests (GET, POST, PUT, DELETE), inspect response payloads and status codes, and test CSRF token retrieval directly within SAP GUI."*
